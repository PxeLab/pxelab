把「网络」编码进 >_

v1 反馈：图形成立但读作「通用终端」，PXE 的网络层缺失。v2 在 C&G 哲学不变的前提下（纯几何、一个 idea、负空间即含义、零渐变、任何尺寸成立），探索 3 个把 PXE 显式编码进 mark 的变体，并给出推荐。PXE 的真实流程是：裸机开机 → 广播 DHCP discover → server 应答 → 镜像经 TFTP/HTTP 流入机器——三个变体分别编码这条链路的不同段落。

01 / Three Variants

变体并排对比

Variant A · Recommended

Discover —— 光标即机器，机器在广播

光标块变成一台裸机，头顶两道同心弧 = 它开机瞬间发出的 DHCP discover 广播——PXE 流程的第一步。尖括号仍是 server 应答/镜像流入的方向。一个 mark 编码了 client→network→server 的完整握手。

取舍：弧线是小尺寸最先糊的细节，favicon 版减为单根加粗弧；换来三个变体中唯一「双向」的网络语义。

Variant B

Stream —— 包组成的箭头

尖括号由 5 个像素方块（数据包）拼成，流向光标——OS 镜像拆成包、经网络流进裸机。编码的是 PXE 链路中 TFTP/HTTP 传输的那一段。

取舍：像素化最「数字原生」，16px 下仍成立；但丢掉的实心箭头让「方向感」变弱，且像素风在 dev tool 里偏常见。

16px
32px
Variant C

Subnet —— 一对多的层叠

>>_：两个层叠尖括号 = 同一份镜像同时推向整个网段——一台 server，n 台裸机。编码的是 PXE 的广播/组播一对多本质。

取舍：三个变体中小尺寸最稳、几何最纯粹；但 >> 在 shell 里是「追加」操作符，网络语义最隐晦，需要解释。
