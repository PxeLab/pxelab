# PxeLab 前端设计评审（Impeccable critique）

Method: dual-agent (A: general design review · B: general detector + headless render evidence)

说明：两个子代理的 in-app 浏览器连接均不可用，覆盖层未能注入。B 改用检测器的无头 URL 扫描（真实 Chromium 渲染，5 条路由）；A 用无头 Chromium 截图核验。目标为 `web/src`，运行于 http://localhost:5173（Operate 模式：PXE 服务器管理台）。

## 设计专属性判定

**LLM 评估**：信息模型确实是 PXE 产品的（服务拓扑以 DHCP/TFTP/HTTP/DNS/NFS 为主轴，含端口、协议、运行时长；DHCP 的 Offer/Ack/Nak、Discover/Request、拒绝/未授权；PXE 引导记录 → 录入主机 → 装机的闭环；Quick Install 的 kernel/initrd 就绪门禁、应答模板缺失阻断）。约 70% 结构是产品专属、30% 是通用 CRUD 外壳：五个等权 KPI、五个等权服务卡、三张图表卡、蓝色主按钮、`rounded-2xl`、Inter，换掉文案就是任何设备管理台；17 项侧栏大量复用通用 Lucide 图标（FileCode 同时用于引导菜单/应答模板/基线脚本，HardDrive 同时用于文件管理/安装任务）。产品在 6 套调色板、5 档圆角、macOS 玻璃质感、主题过渡动画上投入很多，却在 DHCP 变更的预览/差异/回滚上投入很少——这是最明显的"装饰优先于操作安全"。

**确定性扫描**：源码扫描 105 个文件，3 条（2 条计数 + 1 条建议）：`overused-font`（`web/src/index.css:140` Inter）、`ai-color-palette`（`web/src/pages/Store.tsx:272` 紫色渐变）、建议级 `bounce-easing`（`SettingsModal.tsx:767`）。元素级规则在源码模式不生效，因此用检测器的无头 URL 扫描补足：

检测器与人工评审高度互证：双方都指向 `--foreground-muted: #94a3b8`（`index.css:15`）在浅色背景上只有 2.4–2.6:1、主按钮白字/`#3b82f6` 3.7:1、状态胶囊 1.8–3.3:1，以及 9–10px 的状态/元数据文本。误报/低价值项：`overused-font` 无法区分"刻意中性"与"跟风"；`ai-color-palette` 命中的是 Store 里 40×40px 图标块而非整页渐变；`bounce-easing` 是下载状态上的瞬时反馈而非过渡曲线；`tiny-text` 与 `undersized-ui-text` 对同一批 9px 节点重复计数；`nested-cards` 命中的是仪表盘服务卡内的紧凑列表行，材质中等。

**可视化覆盖层**：不可用。子代理的 in-app 浏览器未连接，未能注入 `detect.js`，因此没有用户可见的覆盖层；以上来自检测器无头渲染结果。

## 总体印象

界面骨架是可信的：服务拓扑、状态点、端口/协议、PXE 引导记录闭环都说明设计者懂这个产品。问题在于它把"展示状态"当成了首页目标：仪表盘把同一份健康信息重复四遍，真正需要决策的内容（刚发生了什么、哪台机器要处理、这次改动会影响谁）被推到首屏之外；同时，最危险的操作（停止全部服务、应用 DHCP 配置、删除主机）反而最轻、最缺少后果说明。最大的机会不是换皮，而是把首页改成"变更与决策面板"，并给所有会中断引导的操作补上爆炸半径、差异预览与回滚。

## 做得好的

1. **引导记录 → 录入主机 → 装机是真正的产品级设计**：未认领的 PXE 记录是一等公民，带未认领计数、MAC、最后出现时间、loader、入口/菜单上下文；"录入主机"把 MAC 带进创建表单（`Hosts.tsx:270-311, 385-390`），形成闭环。
2. **Quick Install 不允许静默失败**：只提供 kernel/initrd 已就绪的系统（`QuickInstall.tsx:102-112`），应答模板缺失时是显式红色阻断并可跳转修复（`422-432`），批量结果逐 MAC 列出成功/失败（`537-560`）。
3. **有真实的设计系统地基**：语义令牌（`index.css:109-136`）、明暗主题、主色/圆角派生、Button/Card/Modal/Toast/ConfirmDialog/DataTable 等原语、输入焦点环、骨架屏、带最近访问与主机搜索的命令面板。问题是应用不均匀，不是没有系统。

## 优先问题

### [P1] 破坏性与全局操作没有"爆炸半径"

- **是什么**：一键停止/一键重启从悬停展开的下拉里立即执行（`AppShell.tsx:182-227`）；删除主机/文件的确认文案不点名对象（"确定要删除该主机吗？"）；DHCP 接口保存直接调用 API 并关窗（`DHCPConfigTab.tsx:91-116`）；删除接口的确认按钮还用主色而非危险色（`247`）。
- **为什么重要**：这是 PXE 服务器。停掉 DHCP/TFTP 会中断正在引导的机器，错误的子网/地址池设置能让整个实验室失联。当前 UI 让最危险的动作最容易误触（10px 的小红字按钮相邻排布），却最不解释后果。
- **怎么修**：每次确认都写清对象与后果，例如"停止全部服务？DHCP（以太网）、TFTP、DNS、NFS 将停止，当前 3 台正在引导的机器会失败"。DHCP 增加"应用并重启 DHCP"步骤，展示 CIDR/地址池/next-server 的差异与该子网活跃租约数；危险确认统一用 danger 样式；一键停止/重启必须确认，一键启动不必。
- **建议命令**：`/harden`（主）、`/clarify`

### [P1] 仪表盘 KPI 来自被截断的分页，数字可能是假的

- **是什么**：`getHosts({page:'1', size:'8'})` 与 `getEvents({page:'1', size:'12'})` 喂给"在线主机"和"今日启动"（`Dashboard.tsx:92-99, 163-175`）。有 50 台主机时，"在线主机"只是前 8 台里的在线数；事件超过 12 条时，"今日启动"只统计最新 12 条里的今日启动。"运行服务"统计全部运行服务（6 个），但下面只渲染 5 张服务卡，ProxyDHCP 不可见（`152-158 vs 179`）。HTTP 请求数是累计值，而 2xx/4xx/5xx 是窗口增量（`222-255`），同一张卡里的数字时间基准不一致。
- **为什么重要**：运维靠仪表盘决定是否介入。一个自信显示的"0 在线"如果只代表"前 8 台里没有在线"，比不显示更糟。
- **怎么修**：为在线主机/今日启动增加显式 count 接口或聚合指标；若只能采样，就标注"前 8 台"或显示"—"；渲染第 6 个服务（ProxyDHCP）或解释计数；每个指标标时间基准（"自启动以来"/ "最近 5 分钟"）。
- **建议命令**：`/harden`（主）、`/clarify`

### [P1] 弹窗与表格模型无法键盘/读屏操作

- **是什么**：`Modal` 没有 `role="dialog"`、`aria-modal`、`aria-labelledby`，打开不移动焦点，焦点陷阱只在焦点恰好在首/末元素时生效（`Modal.tsx:24-64`）。实测打开"新建主机"后 `document.activeElement` 仍是背后的新建按钮，下一次 Tab 走到侧栏的"主机管理"。`DataTable` 用 `<tr onClick>` 做唯一行操作且无 `tabIndex`（`DataTable.tsx:115-118`），可排序 `<th onClick>` 无按钮语义与 `aria-sort`（`102-107`）。文件管理把删除藏在 `opacity-0 group-hover:opacity-100`（`Files.tsx:144-149`），键盘无等价入口；37 个图标按钮无名称。弱化文本/状态色在 9–12px 下仅 2.28–3.09:1。
- **为什么重要**：键盘运维无法打开主机、排序表格或发现文件删除；读屏用户不知道弹窗已打开；低视力用户在 200% 缩放下读不清状态。
- **怎么修**：给 Modal 加 `role="dialog" aria-modal="true" aria-labelledby`，打开时聚焦首字段或对话框容器，关闭还原焦点，背景 inert；行导航改成真链接或 `tabIndex=0` + Enter/Space；排序表头改成按钮并维护 `aria-sort`；行操作常显或在 `focus-within` 时显示；把弱化文本提升到 12px 下达 4.5:1 的令牌，并停止用 9–10px 承载可操作/状态文本。
- **建议命令**：`/harden`（主）、`/typeset`、`/colorize`

### [P2] 三级信息架构在移动端坍塌，桌面端命名过载

- **是什么**：移动端没有到非 DHCP 设置页的入口（实测 `/services/dhcp` 390×844 时 `subnavVisible:false`），汉堡菜单里的"服务配置"只会回到 DHCP（`AppShell.tsx:441`）；DNS/TFTP/NFS/SMB 只能靠 ⌘K。桌面侧栏 10 项混合了服务、钩子、Webhook、引导选项、系统目录。`/quick-install` 移动端顶栏标题显示"仪表板"，因为 `pageTitle()` 只匹配导航路径（`378-390`）；仪表盘还同时渲染移动端标题和页面标题两个 `<h1>`。
- **为什么重要**：移动端处理启动失败的运维无法从 DHCP 切到 TFTP；第一次使用的人无法把"系统目录"映射到"导入操作系统的地方"。
- **怎么修**：把设置侧栏改成移动端抽屉/Sheet，由可见的"服务"胶囊触发；把非服务项（引导选项、系统目录）移出服务侧栏，归入基础配置或新建"引导"组；统一一套词汇：Boot Menu（Profiles）/Boot Options（BootSettings）/Boot Catalog（NetbootCatalog）/OS Images/Hub；修 `pageTitle()` 覆盖全部路由并去掉重复 `<h1>`。
- **建议命令**：`/shape`（IA）、`/adapt`（移动）、`/clarify`（命名）

### [P2] 仪表盘用重复状态淹没可执行信号

- **是什么**：事件流之前/周围有 14 个近似等权块：服务条、5 个 KPI、5 个详情卡、3 个图表卡（`Dashboard.tsx:284-580`）。三张图里两张是"暂无数据"却各占 208px；近期事件在 900px 视口下从 y≈962 才开始；KPI 骨架屏没有高度（`341-345`），数据到达时会跳动。
- **为什么重要**：运维首页应该先回答"什么变了、哪里坏了、需要我做什么"。当前更像状态清单，不是决策面。
- **怎么修**：把服务条、运行服务 KPI、5 个详情卡合并为一张紧凑服务表（健康、端口、运行时长、每服务一个异常数字）；把近期事件提到首行；空图表折叠成一行"暂无数据"或放进标签页；5 个 KPI 只有在准确且可点进列表时才保留；骨架屏给固定高度。
- **建议命令**：`/distill`（主）、`/layout`

## 次要观察

- 主机"删除"列只有 60px，1440px 下"删除"竖排换行（`Hosts.tsx:352-354`）。
- 文件时间戳列 8rem 且未 `whitespace-nowrap`（`Files.tsx:116-121`），每行被撑成两行。
- MD5 截断到 16 字符且无复制入口（`Files.tsx:124-134`），校验用途被削弱。
- Store 已加载状态仍把刷新按钮叫"重试"（`Store.tsx:174-177`）。
- Store 在外壳 `p-8` 内再套 `p-6`（`Store.tsx:164`），整页相对其它页右下偏移 24px。
- Store 标签用标签字符串当 React key（`Store.tsx:319-321`），重复 `windows`/`linux` 会触发 key 警告。
- 事件总数为空时渲染 `0+`（`Events.tsx:87`）。
- `<html lang="zh-CN">` 是静态的；切到英文后文档仍声明中文，读屏可能按中文规则读英文。
- Button 使用 `font-sans`（`Button.tsx:25`），落到系统字体栈，与 body 的 Inter 不一致。
- Google Fonts 是外链（`index.html`），在典型离线/隔离的 PXE 网络会静默降级字体。
- 设置弹窗的令牌警告在普通加载时就出现，因为输入显示的是掩码值而条件检查的是完整值（`SettingsModal.tsx:306-324`）。
- DHCP 删除接口确认用 `variant="primary"`（`DHCPConfigTab.tsx:247`），与其它危险确认不一致。
- DHCP 多行校验被 `errs.join('\n')` 放进普通 `<span>`（`DHCPConfigTab.tsx:93` + `Toast.tsx:134`），三条子网错误变成一句连读。
- Profiles 的 select 用 `outline-none` 且无替代焦点样式（`Profiles.tsx:468, 506`），键盘焦点消失。
- `prefers-reduced-motion` 只覆盖主题过渡（`index.css:215-220`），脉冲状态点与 shimmer 骨架仍在动。
- 仪表盘第 6 个运行服务不可见：头部说 6 个运行，详情只渲染 5 个。
- 900px 高视口下侧栏被裁切（内容 807px / 可视 779px），"实时日志"被设置页脚挡住，只有 6px 滚动条提示。

## 值得思考的问题

1. 如果这个产品只能保留一个屏幕，它该是五张服务卡 + 五张 KPI 卡，还是一条按优先级排序的"什么变了 / 什么坏了 / 需要什么决策"？
2. 为什么 DHCP、TFTP、DNS、NFS、SMB 的健康在仪表盘上出现四次，而它们的配置却藏在三级深处、且父按钮会静默选中 DHCP？
3. PXE 服务器的"变更控制"应该长什么样：DHCP 地址池差异、受影响租约数、下一次启动的 dry-run、一键回滚？看到这些之后，运维还会信任一个裸的 Save 吗？
4. "快速装机"应该是一个 `/quick-install` 向导，还是引导记录队列（未认领机器已经在那里）的主操作？
5. 如果命令面板能执行动作（停 TFTP、重启主机、打开最新租约），17 项侧栏还需要一直可见吗？
6. 运维在空服务器上的前 60 秒必须学会什么？"0 / 暂无数据 / 未连接"教会了其中哪一条？
7. 一个自托管、经常离线隔离的 PXE 服务器，真的需要社区 Hub、六套调色板和 macOS 玻璃吗？同样的投入放在离线文档、首次引导和安全应用上会不会更值？
8. 哪些 PXE 事实绝不能含糊：某 MAC 会拿到哪个引导文件、会落到哪个子网、应答模板是否就绪。为什么它们不是屏幕上最大的三件事？
