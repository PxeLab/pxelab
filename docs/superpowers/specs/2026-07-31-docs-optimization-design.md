# 产品文档系统优化设计（website/docs）

日期：2026-07-31
状态：已批准（用户已确认全部三节设计）

## 1. 背景与目标

当前 `website/docs`（VitePress 双语站点，中文根目录 + `en/`）存在以下问题：

1. **全站零图片** — 除 logo 外没有任何 Web UI 截图，界面全靠文字描述
2. **上手路径偏技术化** — getting-started 从系统要求表开始，含 SQLite/数据目录等实现细节，缺少「第一次装机成功」的体验设计
3. **术语门槛高** — PXE/NBP/ProxyDHCP/Option 93 等术语在入门文档直接出现
4. **指南是功能清单而非任务导向** — 多数 guides 是「页面有什么功能」，缺少「想做 X → 去哪做」的路径
5. **信息架构问题** — 孤立页（architecture、dhcp-modes、sanboot、troubleshooting、release-notes、contributing）、重复（ipxe-build 两份、faq 与 troubleshooting 重叠）、易混淆（architecture / architecture-advantages / boot-architecture）
6. **细节** — getting-started 中 GitHub 链接为 `github.com/user/pxelab` 占位符

目标：文档能指导用户快速了解、上手并使用 PxeLab——零基础用户 15 分钟内跑起 PxeLab 并完成第一次网络装机。

## 5. 写作规范

- **术语策略**：首次出现时一句话解释（PXE、NBP、ProxyDHCP、iPXE…），不堆缩写；协议细节指向进阶主题
- **任务导向**：每页开头回答「解决什么问题/什么时候用」，主体是「想达成 X → 点哪里 → 你会看到什么」步骤，末尾给相关参考链接
- **移除实现细节噪音**：如 getting-started 的「初始化 SQLite 数据库」等内部行为
- **保留技术深度**：进阶主题/参考区不因入门改造而降级
- **教程与指南分工**：教程 = 场景驱动、跨页面的完整流程；指南 = 单功能深度操作。教程链指南，不重复展开

## 10. 风险

- 截图需本机跑起 PxeLab 后端（8080 HTTP 即可，无需 admin）；DHCP 端口 67 绑定失败时，仅截图不显示 DHCP running，不影响其余页面（实施时先验证）
- 中英结构需同步（en 侧边栏镜像 zh），内容翻译滞后于中文是预期内的
- website 为 git submodule，docs 改动在子模块仓库内提交
